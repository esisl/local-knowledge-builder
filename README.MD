Поэтапный план работ (проверяемые промежуточные результаты)
Каждый этап завершается командой/скриптом, который выдаёт конкретный артефакт. Не переходите к следующему, пока текущий не проходит проверку.

🔹 Этап 0: Среда, репо, базовый инференс
Цель: Рабочее окружение, Git, проверка GPU-инференса.
Стек: Python 3.10+, llama-cpp-python, torch (CPU-only для эмбеддеров позже).
Действия:
Создать репо, добавить .gitignore, requirements.txt.
Установить llama-cpp-python с CU121 wheel.
Скачать Qwen2.5-7B-Instruct-Q4_K_M.gguf.
Написать test_llm.py: загружает модель, принимает строку, выводит ответ.
Проверка: python test_llm.py "Кратко объясни, что такое Erlang." → ответ приходит за <3 сек, VRAM ~4.5 ГБ (через nvidia-smi), ошибок нет.

🔹 Этап 1: Сбор и очистка сырых данных
Цель: Тема → список URL → чистый Markdown с метаданными.
Стек: duckduckgo-search, Crawl4AI/trafilatura, pydantic.
Действия:
Скрипт принимает список запросов (или генерирует через локальную LLM).
Ищет → парсит → сохраняет в data/raw/{domain}_{timestamp}.md.
Метаданные: url, title, fetched_at, word_count.
Проверка: Запустить с 3 запросами. Проверить 5 случайных .md файлов: нет рекламы, навигации, JS-мусора. Текст читаем. Метаданные заполнены.

🔹 Этап 2: Дедупликация и чанкинг
Цель: Убрать дубли, отфильтровать нерелевантное, разбить на чанки.
Стек: datasketch (MinHash), trafilatura/regex, LlamaIndex MarkdownNodeParser или кастомный сплиттер.
Действия:
Чтение data/raw/*.md.
MinHash с порогом 0.85 → удаление дублей.
Чанкинг: 500–700 токенов, перекрытие 100, сохранение заголовков в метаданные.
Вывод в data/chunks/chunks.jsonl (строка = {id, text, metadata}).
Проверка: wc -l data/chunks/chunks.jsonl > 0. Открыть 3 строки: текст не обрывается посередине таблицы/кода, metadata содержит source_url,
chunk_index, parent_heading. Дубли удалены (сравнить хеши похожих документов).

🔹 Этап 3: Эмбеддинги и векторный индекс
Цель: CPU-эмбеддинг → локальное хранилище.
Стек: sentence-transformers (BAAI/bge-small-en-v1.5), chromadb.
Действия:
Загрузить эмбеддер на CPU.
Пакетно векторизовать чанки.
Сохранить в chroma_db/ (persist).
Проверка: python test_retrieval.py "Erlang concurrency model" → возвращает 3–5 релевантных чанков с similarity_score > 0.7. Проверить вручную, что чанки относятся к теме, а не к мусору.

🔹 Этап 4: Генерация с сессией (llama.cpp)
Цель: RAG-инференс + сохранение контекста.
Важно: llama.cpp не сохраняет «сессию» в виде файла на сотни МБ. Сохраняйте историю сообщений + кэш промпта.
Стек: llama-cpp-python, jinja2 (для системного промпта), json (история).
Действия:
Загрузка модели + эмбеддера (из Этапа 3).
Цикл: запрос → ретривал → формирование промпта → генерация → сохранение {role, content}.
При старте загружать session.json, восстанавливать историю, использовать cache_prompt=True для ускорения.
Проверка: Задать 3 вопроса подряд. Перезапустить скрипт, загрузить сессию, задать 4-й вопрос. Модель помнит контекст, не пересказывает историю с нуля. Время ответа стабильно.

🔹 Этап 5: Интеграция и экспорт для air-gapped
Цель: Один конфиг, один скрипт, архив для переноса.
Стек: pyyaml, tarfile, hashlib.
Действия:
config.yaml: тема, запросы, модель, пути, параметры чанкинга.
run_pipeline.py --mode build → полный пайплайн 1–4.
run_pipeline.py --mode export → архив topic_export.tar.gz (веса, chroma_db/, config.yaml, session_schema.json, checksums.sha256).
run_pipeline.py --mode import → распаковка + проверка хешей + валидация БД.
Проверка: Удалить chroma_db/, запустить import. Система поднимается, отвечает на тестовый запрос. Хеш-суммы совпадают, ошибок целостности нет.

🔹 Этап 6: Минимальный UI для генерации
Цель: Замена CLI на графический ввод/вывод.
Стек: customtkinter или PyQt6.
Действия: Поле ввода, кнопка «Отправить», текстовое поле ответа, список источников (url, score). Подключить к Этапу 4 через threading/asyncio.
Проверка: Запуск без зависаний, корректный перенос строк, источники кликабельны или копируются.

OOM на 3060: Если n_gpu_layers > 35 или n_ctx > 8192, модель уйдёт в RAM. Используем --keep 512 в llama-cpp-python и смотрим за nvidia-smi.
Если similarity_score < 0.6, система будет глючить. Добавим min_score=0.65 и top_k=4. Если источников мало, fallback: "В базе нет релевантных данных. Уточните запрос или расширьте тему."
Сессия растёт бесконечно: llama.cpp не чистит историю автоматически. Ставим max_history_tokens=4096, удаляем старые сообщения, оставляя системный промпт + последние 2–3 обмена.
Windows-специфичные ошибки путей/кодировок: файлы нужно с encoding="utf-8", pathlib, NOT os.chdir().
